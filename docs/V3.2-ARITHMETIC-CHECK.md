## 2. N3 collision claim (§4) — ONE ERROR
The `off_by_one_per_group` / `counted_groups_as_group_size` collision occurs exactly when
`per_group − 1 == groups`.

| Shape | per−1 | groups | Result |
|---|---|---|---|
| 2×3 | 2 | 2 | **collides** |
| 3×3 | 2 | 3 | separates |
| 3×4 | 3 | 3 | **collides** |
| 4×3 | 2 | 4 | separates |
| **4×5** | **4** | **4** | **COLLIDES** |
| 2×5 | 4 | 2 | separates |

v3.2 §4 states the collision is *"false for 3×3, 4×3, 4×5, 2×5."* **4×5 is wrong — it collides.**
Correct statement: collision on **2×3, 3×4, 4×5**; separation on **3×3, 4×3, 2×5**.

**Design impact: none.** The chosen diagnostic node is **4×3**, which does separate
(`[2,2,2,2]` vs `[4,4,4,4]`). The error is in the prose list, not the decision. **PATCH item:**
fix the sentence; also note that 4×5 is a demo-class shape where `[4,4,4,4]` will classify as
`ambiguous` and route to 4×3, same as 3×4 does.
